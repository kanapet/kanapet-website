# Production publishing

The source of truth is `public/data/products.json` and `public/data/categories.json`.
`public/js/data.js`, static product facts and cache fingerprints are generated by
`python tools/build_release.py`. Never edit generated facts separately.

Confirmed specifications and product image hashes are in
`content/confirmed-products.json`. Change an approval record only when the user
explicitly changes that fact or image. The checker blocks accidental regressions.

Commit the complete reviewed site to GitHub `main`. Cloudflare Git Builds is the
only production publisher. Its existing `npx wrangler deploy` command invokes
the checked-in `build.command`, which generates and validates the release first.
Direct local Wrangler production uploads fail the build hook. This is an
operational guard, not a replacement for controlling Cloudflare account access.
Do not bypass it with `--no-bundle`, alternate config files or environment spoofing.

`public/release.json` identifies the exact generated release and asset hashes.
GitHub Actions checks the same release, then compares the live data, HTML,
JavaScript and confirmed images with those hashes. A deploy is complete only
after this verification succeeds. HTML/data revalidate and script/style URLs
include content hashes, so mobile browsers obtain changed assets.

For local previews run `python tools/build_release.py` and serve `public/`.
For rollback, revert the problematic Git commit and push `main`; never deploy
an old local directory. Retired directories under `outputs/` are not publishers.
